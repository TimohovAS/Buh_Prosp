# Handoff: Work Diaries Module

Дата handoff: 2026-07-10 (обновлено после переработки Claude)

## Переработка 2026-07-10 (вторая итерация)

Роль модуля зафиксирована: дневник — аналитика работ, деньги за материалы живут в модуле Расходы.

### Материалы: источник и привязка к расходам

- строка материала имеет `source`: `stock` (со склада, стоимость — оценка) или `expense` (привязан к расходу проекта через `expense_id`);
- привязанные материалы НЕ прибавляются к затратам объекта повторно (они уже в Расходах);
- расход для привязки должен принадлежать тому же проекту (иначе 400), сторнированные расходы не привязываются;
- пустая сумма привязанной строки = вся сумма расхода (подставляется на бэкенде);
- `quantity` теперь число, добавлена единица измерения `unit` (kom|m|m2|m3|kg|t|l|pak|h) — расход материалов можно агрегировать;
- endpoint `GET /work-diaries/expense-options?project_id=` — расходы проекта для привязки.

### Затраты по объекту

- endpoint `GET /work-diaries/project-costs?project_id=&date_from=&date_to=`:
  итого = расходы проекта (Expense, нетто со сторно, без cash_transfer) + труд по дневнику + надбавки + материалы со склада;
- вкладка «Затраты» на странице дневников показывает эту разбивку.

### Деньги

- коэффициент сверхурочных вынесен в настройки предприятия (`enterprise.work_diary_overtime_multiplier`),
  по умолчанию 1.26 (Закон о раде РС: минимум +26%); старое зашитое 1.14 признано ошибочным,
  миграция обновляет 1.14 -> 1.26 в существующих записях;
- дневница и питание считаются НА ЧЕЛОВЕКА (умножаются на число работников), проживание — на бригаду целиком;
- погода хранится кодом (sunny|cloudy|rain|snow|wind|fog), фронтенд переводит, печатные формы маппят в сербский;
- PATCH с `duration_hours` без времен теперь сбрасывает сохраненные start/end (раньше молча игнорировался).

### UI

- страница распилена на компоненты `frontend/src/components/work-diaries/`
  (EntryModal, MetaModal, PrintDiary, PrintReport, CostsTab, workDiaryUtils) — страница ~430 строк;
- вкладки: Записи / Затраты / Дневник / Отчет;
- форма записи: обязательный минимум + свернутые секции «Надбавки» и «Для строительного дневника»
  + живой расчет денег (чел-часы, труд, надбавки, материалы, к выплате, к фактурированию);
- ручная ставка бригады больше не сбрасывается при смене состава; авто-ставка показана подсказкой
  с кнопкой «Применить»; предупреждение, если у выбранных работников нет дневной ставки
  (weekly/monthly — авто-ставка 0);
- реквизиты объекта вынесены из основного потока в модалку «Реквизиты объекта»;
- таблица записей с сортировкой по клику на заголовки; колонка «Затраты» вместо «Материалы».

### Известные ограничения / следующие шаги

- одна запись = одна бригада с общим временем; часы на отдельного работника не ведутся;
- выплаты работникам (раздел Работники/Касса) не сверяются с начислениями дневника автоматически;
- экспорт печатных форм в Excel/PDF без браузерной печати не сделан.

## Что сделано (первая итерация)

Добавлен раздел `Дневники работ` (`/work-diaries`) для учета выполненных работ и печатных отчетов:

- учет записей по проекту, нескольким работникам и датам;
- расчет длительности смены по `start_time` / `end_time` или ручному значению `duration_hours`;
- расчет человеко-часов как длительность смены × количество исполнителей;
- обычные и сверхурочные человеко-часы (граница — 8 часов общей смены);
- фиксация общей ставки бригады на момент записи;
- дневница, питание, проживание;
- материалы и оборудование по строкам;
- метаданные объекта для печатных форм;
- печатный `Грађевински дневник`;
- печатный отчет `Евиденција радних сати и утрошеног материјала`.

### Несколько работников в одной записи

- запись хранит сотрудников только через связь many-to-many `work_diary_entry_workers`;
- API создания и изменения принимает только `worker_ids`, одиночного `worker_id` больше нет;
- фильтр по работнику находит запись, если сотрудник входит в выбранную бригаду;
- ставка записи по умолчанию равна сумме почасовых ставок выбранных работников;
- введенная вручную ставка считается общей ставкой всей бригады;
- список, сводка и обе печатные формы показывают всех выбранных работников;
- запись можно создать и отредактировать через одну модальную форму, включая работников и материалы;
- новая запись открывается в стандартном модальном окне, исполнители выбираются компактным multi-select;
- даты в фильтрах и форме используют общий календарь `DatePicker`, как остальные разделы программы;
- вкладки `Дневник` и `Отчет` требуют выбрать один проект и показывают явную подсказку вместо пустой области;
- печать доступна только для выбранного проекта с записями;
- Alembic-ревизия `20260710_0004` переносит существующие назначения и удаляет старую колонку `worker_id`;
- Alembic-ревизия `20260710_0005` переименовывает неоднозначные колонки длительности и общей ставки бригады.

### Контракт часов без обратной совместимости

- вход API: `duration_hours`, `team_hourly_rate_snapshot`;
- ответ записи: `duration_hours`, `person_hours`, `regular_person_hours`, `overtime_person_hours`;
- ответ сводки: `person_hours`, `regular_person_hours`, `overtime_person_hours`;
- старые поля `hours`, `regular_hours`, `overtime_hours`, `hourly_rate_snapshot` API больше не принимает и не возвращает;
- стоимость труда считается по длительности смены и общей ставке бригады, без повторного умножения на работников;
- ставка фактурирования проекта применяется к человеко-часам;
- сумма к выплате включает работу, дневницу, питание и проживание.

## Как восстановить базу на другом компьютере

Перед восстановлением остановить backend/dev-сервер, если он запущен.

Из корня проекта:

```powershell
New-Item -ItemType Directory -Path .codex_tmp\db_restore -Force | Out-Null
Expand-Archive -LiteralPath .\handoff\prospel_db_work_diaries_2026-07-10.zip -DestinationPath .\.codex_tmp\db_restore -Force
Copy-Item -LiteralPath .\.codex_tmp\db_restore\prospel.db -Destination .\prospel.db -Force
.\venv\Scripts\python.exe -m alembic upgrade head
```

После этого можно запускать:

```powershell
.\start_dev.cmd
```
